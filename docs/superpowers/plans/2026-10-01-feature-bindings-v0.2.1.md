# Feature bindings v0.2.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Let Claude, Codex and Cursor users explicitly bind individual core or extension phase invocations to features, including when continuing a session with stale branch metadata, without changing token accounting.

**Architecture:** Store checkout-scoped invocation bindings in private Git runtime state and apply them before timeline/branch fallback. A checkpoint command selects an observed invocation, previews its destination, and persists it only on explicit apply; it serves both ongoing workflows and separately selected historical repairs. The after-specify hook provides the initial checkpoint; later core and extension phases use their own explicit checkpoints and never inherit a session-wide feature.

**Tech Stack:** Python 3.9+, existing runtime adapters and phase classifier, JSON, pytest, Spec Kit 1.0.12+.

**Spec:** [Usage Bridge runtime design, section 12: v0.2.1 amendment](../specs/2026-10-01-usage-bridge-v0.2-design.md#12-v021-amendment-continuing-sessions-with-stale-feature-attribution). Sections 1–11 remain the v0.2.0 baseline; this plan implements section 12 and preserves their accounting, privacy and compatibility constraints.

## Global Constraints

- Python 3.9+ and Spec Kit 1.0.12+ remain the baseline.
- The extension is distributed as files, not as a Python package.
- Preserve the pinned token-usage commit and hashes. All vendor calls pass through `tu_compat.py`; new adapters do not mutate its private adapter registry.
- Never commit raw hook payloads, transcripts, credentials, account IDs or absolute paths.
- Activity-only token fields and costs are null in JSON and unavailable in Markdown.
- Project-level `constitution` retains its existing semantics.
- A feature binding cannot resolve ambiguous token intervals or manufacture usage.
- Bindings must not leak between runtimes, sessions or checkouts.
- Preview changes neither bindings nor feature reports.
- Preserve schema v2, existing Claude event behavior, author/machine separation, deadlines, locks and atomic output replacement. No parent/child accounting changes.
- Target v0.2.1 on existing branch `codex/v0.2-design`. Prepare the release and update PR #5; do not merge or publish. Do not install or apply repairs in another repository.

## Review Focus

1. Concurrent workflows overwrite feature.json: only the caller's explicit feature selects the destination (Task 2).
2. Repeated phases or duplicate start timestamps: no arbitrary invocation selection, including with `--latest` (Tasks 1–2).
3. Windows path aliases, traversal and symlinks across checkouts: normalize identity and reject destinations outside the selected checkout (Tasks 1–2).
4. Repair moves the last local run out of a feature: remove its obsolete local assignment while retaining unavailable history and other authors' files (Task 1).
5. Delayed counters, duplicate hook delivery or interruption after binding persistence: retries keep one binding and preserve measured usage (Tasks 1–2).
